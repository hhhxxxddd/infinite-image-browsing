# 性能排查记录（2026-09-23）

## 范围与样本

检查了目录图加载、增量扫描、媒体列表和翻页、文件夹范围过滤、缩略图、文字与 AI 检索。当前本机数据库有 498 条媒体、6 条已扫描目录；这是功能验证样本，无法代表十万张图片或网络盘的耗时。

## 已处理

| 路径 | 发现 | 调整 |
| --- | --- | --- |
| 子目录扫描 | 已记录目录的修改时间原先只精确到秒，短时间连续增删可能漏判；启动命令只扫描根目录时也可能跳过已变化的子目录。 | 目录修改时间改用纳秒；启动命令从过期目录列表扫描。页面的过期目录扫描本来会包含子目录，现也在“目录”页运行。旧时间记录升级后会触发一次补扫。 |
| 目录图 | 打开页面时递归读取多层节点，每个目录一次请求，宽目录可能造成大量并发请求与节点渲染。 | 初次仅读取根目录的直接子目录；更深的层级由节点按需展开。仅列目录时后端不再为每个子目录读取完整文件元数据。 |
| 媒体选择 | 全选后，对每张可见卡片用数组线性查找选中状态；拖动选中项时重复构造路径数组。 | 复用选中索引集合与拖动路径集合。 |
| 默认排序翻页 | 即使没有手动排序记录，也使用 `OFFSET` 跳过前面所有行。 | 没有手动排序时使用日期和 ID 游标；存在手动排序时保留原有位置顺序。 |
| 文件夹范围查询 | `substr(image.path, ...)` 条件无法利用现有路径索引。 | 改为字面路径范围条件，保留目录边界与“不含子文件夹”语义；Windows 增加忽略大小写的路径索引。实测 SQLite 查询计划从按日期扫描改为 `SEARCH image USING INDEX image_idx_path (path>? AND path<?)`。 |
| 卡片标签 | 每张卡片以数组展开和逐项查找生成标签状态，标签多时产生不必要的重复工作。 | 改为一次建立已选 ID 集合，再线性映射标签。 |
| AI 状态 | 开启画面搜索时每 2 秒请求模型状态；索引数量统计需要扫描媒体表。 | 改为每 10 秒轮询，且防止上次请求未结束就再次发出。 |

## 后续容量风险

| 优先级 | 路径 | 原因与建议 |
| --- | --- | --- |
| 高 | 语义搜索 | 每次查询遍历全部已索引图片，并对每张图片执行文件状态检查和向量点积。图片达到数万以上时应考虑向量索引或分批向量计算，并保留索引失效检查。当前没有大型图库基准，尚不宜直接替换排序算法。 |
| 中 | 目录变化检测 | 可见页面每分钟对所有已记录目录执行文件状态检查；本机 6 个目录负担很小，网络盘或数万目录时可能明显变慢。可考虑系统文件变更监听与低频完整核对。 |
| 中 | 已使用手动排序的深翻页 | 为保留自定义位置，仍使用 `OFFSET`，深页会反复跳过前面行。可考虑以位置和 ID 建立游标。 |
| 中 | 文字搜索 | 文件名函数、描述匹配及标签子查询在宽泛词下仍可能扫描大量媒体。更大图库可考虑专门的 FTS 索引，先用真实查询日志决定字段与分词方式。 |
| 中 | 极宽的单层目录 | 节点图仍会一次渲染一个目录的所有直接子目录。数千个同级目录时需要分批呈现或画布虚拟化。 |

缩略图已有视口附近加载、磁盘缓存和生成并发限制；媒体列表使用虚拟滚动。它们目前没有显示出同级别的结构性问题。

媒体索引的自动扫描与 Qwen 图片向量索引是两套流程：新增媒体会进入媒体索引，画面搜索所用的图片向量仍需在 AI 入口手动点击“更新索引”。

自动检查以目录修改时间为依据，新增、删除或移动目录项会触发所在目录的扫描；只修改已有文件的内容而不改变其所在目录时，目录可能不会被标记为过期。若需要可靠捕捉这种变更，后续应增加文件变更监听或定期核对文件级时间戳，不能把每分钟的目录检查视作完整文件校验。
