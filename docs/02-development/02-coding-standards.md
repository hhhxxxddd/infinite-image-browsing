# 02 · 代码规范

[文档首页](../README.md) · [开发指南](01-development.md)

## 1. 模块与复用

- `app` 只做启动与组合，feature 不能反向导入；`shared` 不导入 feature、app 或业务 store。
- feature 跨模块访问走显式 public 入口，内部直接导入自身文件，避免循环。组件入口单独导入，保持懒加载；纯函数入口不捆绑组件、HTTP 或 renderer。
- 公共业务规则仍归领域：生成信息解析归 `generation-metadata`，图片模型／渲染归 `image-editor`，媒体筛选归 `media-library`；不为复用一律移进 shared。
- 页面组合，组件展示与局部交互，composable 管会话生命周期，model 处理纯计算。composable 返回具名状态和操作，计时器／请求令牌留在内部。
- 编辑器核心通过宿主接口保存产物和编辑文档，不直接构造工作区键或访问其存储。媒体库显式保存与工作区自动保存保持各自语义；制作文件不是一次性草稿。
- 界面使用 React、Mantine／Mantine hooks 与 Tabler 图标；可独立导入的领域模型、工作区仓储和后端契约保留在 `src`，不得重新引入旧 UI 框架。优先复用 HTTP、数值输入和媒体选择能力，不复制防抖、错误提示、解析或选择实现；仅一次使用的简单表达式不造公共抽象。

后端 routes 管 HTTP、权限和状态码，service 管流程，repository 管 SQL，schemas 管边界数据；小模块无需凑齐全部层级。解析器不依赖 FastAPI、数据库或应用启动，共用基础设施采用具体职责名，不新增综合 `tool.py`／`helpers.py`。

## 2. 命名与类型

| 对象 | 约定 |
| --- | --- |
| 产品／机器标识 | OmniGallery／星空馆；`omnigallery`、`OMNIGALLERY_*`、`omnigallery:*` |
| 前端领域目录 | kebab-case，完整领域名 |
| React 组件、TS 类型 | PascalCase，名称表达用途；类型不用无意义 `I` 前缀 |
| TS 模块／函数／变量 | camelCase；composable 为 `useXxx`，store 为 `useXxxStore` |
| Python 模块／函数／变量 | snake_case；类 PascalCase，常量 UPPER_SNAKE_CASE |
| 布尔值 | 优先 `is`、`has`、`can`、`should` |
| 文档路径 | 英文 kebab-case，目录／主题文件使用 `NN-` 序号；入口为 README |

`media` 覆盖图片、视频、音频，`image` 专指图片，`artifact` 指工作区产物，成果是作品选定的产物。界面统一使用“制作文件”，已有 `draft` 类型／键保留兼容；筛选、表单等未提交输入仍可称草稿。编辑记录和快照是持久数据，不称缓存。保留 ComfyUI、LoRA、VAE 等专名。

`fetch` 表示请求，`load` 表示加载并更新状态，`parse` 解析，`format` 展示，`serialize` 保存编码，`save` 持久化，`open…Dialog` 打开交互。

保持 TypeScript strict；外部 JSON 用 unknown 并校验。不能全局禁用 any、非空断言或模板检查；第三方确实缺类型时，仅在局部记录原因。协议发生真实变换时才集中定义 DTO，避免机械复制每个响应。

## 3. 状态、错误与资源

- 请求开始时捕获媒体／工作区身份；切换对象或卸载后，旧响应不得覆盖当前会话。缓存明确范围、失效条件和刷新入口。
- 保存失败保留草稿；loading 在成功失败后都释放，重复提交保护不妨碍重试。取消、未保存、失败、空内容分别处理。
- 多项标签编辑提交目标集合，服务器事务保存，重试不重复切换；单个收藏／快捷标签仍可使用切换接口。嵌套弹窗只响应所属弹窗的快捷键，不能穿透到外层预览。
- 筛选输入和未提交选择归表单本地草稿，避免重绘媒体列表；对高频播放事件仅发布界面真正需要的变化。昂贵标签搜索可延后更新结果，输入回显不能延后。
- 工作区修改经 `WorkspaceStateStore.transaction` 暂存并提交，不直接写只读缓存或 localStorage。文档、索引与关联同事务保存；跨窗口冲突不自动重放写入，删除后的旧会话不能复活制作文件。
- 错误只由一层展示；调用方自行处理时标记 `handledLocally`，避免全局重复提示。
- 不在模块导入时连接数据库、下载模型或请求服务。同步阻塞逻辑保留线程边界，不跨线程共享默认 SQLite 连接。
- 连接、事务和游标都要明确生命周期；SQLite 事务上下文不等于关闭，使用项目连接边界或 `closing`。
- 后台任务遵守已有并发限制，页面卸载不能丢失完成结果；重启不自动重放付费请求。

## 4. 格式与界面

前端单引号、无分号、2 空格、100 列，由 Prettier 管理；Python 4 空格，由 Ruff 管格式和导入。多语句模板事件提取命名 handler，避免格式化后产生不合法表达式。

不将模板／表单／CSS 压成一行，不保留注释掉的旧实现。长度是审查信号，拆分必须形成真实职责，不使用 `part1`／`misc` 分摊行数。CSS 使用共享语义变量，选择器限定自身界面；详细规则见[设计系统](03-design-system.md)。

不手改生成的 dist、组件声明或锁文件；依赖调整用包管理器同步。产物、缓存、数据库、日志与原始测试素材不提交。

## 5. 检查、测试与清理

统一检查用 `python tools/check.py`。前端单测贴近模型；后端分 unit／integration，共享隔离放 support。验证行为与边界：零权重、特殊字符、原始工作流保留、切换／取消／失败、分组拖动、覆盖和副本保存。

测试使用独立资源，先关客户端与后台任务，再关全部线程连接，最后删临时目录；不碰开发数据库或真实付费任务。云凭据、模型权重、安装包验证单独记录，跳过不算通过。提交前核对动态组件、CLI、静态资源、sidecar、Linux 路径大小写。

Spike 允许舍弃旧应用数据，但媒体、模型、凭据、源码与 Git 不属于清理范围。重置工具默认预览，显式执行仅清理已识别的应用目录，不向父级扩展。
