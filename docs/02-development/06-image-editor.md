# 图片编辑实现

[文档导航](../README.md) · [图片制作](../01-user-guide/02-workbench.md#图片制作) · [工作台实现](07-workbench.md)

ImageStudio 共用工作区和媒体库编辑界面，保存目标由 EditorHub 上下文决定。领域模型位于 `frontend/src/features/image-editor/model`，交互组件位于 `frontend/react/features/editors`。

## 文档与交互

`StudioDocument` v2 保存图层、分组、画布和文字样式。载入校验结构、唯一 ID 和数值，保留全部有效图层与分组。分组保持连续层块，空组用 `stackIndex` 保存位置；整组变换包含隐藏成员并检查成员锁定。

`ImageGroupAssignment` 统一各类图层的归属标签与右键入口，支持多选批量移入／移出和新建分组。`moveStudioLayersToGroup` 原子检查源／目标锁定，保留成员顺序与几何、连续组块及空组位置；无变化时返回原文档，不产生撤销记录。组自身属性保留在常驻面板。

`EditorParameterSlider` 共用图片编辑与 AI 图片加工的单行参数布局，显式传入默认值和单位格式。重置沿用滑条变更回调，已为默认值或只读时禁用；视图缩放与笔刷重置不修改文档。

图片和文字属性按名称、类型设置、公共几何、不透明度排列。`ImagePropertyControls` 共用行与按钮布局，`ImageLayerGeometry` 单独订阅实时变换，统一比例锁定、尺寸、位置、画布对齐、旋转与翻转；`ImageTextProperties` 只负责文字内容与排版。只读、图层锁定及所属分组锁定均禁止修改属性。

`imageStudioGeometry.ts` 统一旋转命中、变换、对齐和裁剪边界。裁剪用原素材归一化坐标累计，按实际选框保留小尺寸裁剪；翻转时反向映射源区域，画框仍使用显示坐标。图片和文字的 `flipX`／`flipY` 随文档保存，旧图片文档默认不翻转；预览和导出共用渲染。源快照保留真实宽高，文字预设、排版与拟合由 `imageStudioText.ts` 提供。

变换和裁剪分别使用 `imageTransformPreviewStore`、`imageCropPreviewStore`。手势按动画帧合并，画布、选框和几何属性订阅同一预览，避免重绘整个编辑器；开始文档保持不变，结束一次提交、一次撤销，取消清除预览。中键／空格平移只更新视口 CSS 位移。

## 预览与导出

`studioPreviewScale` 根据显示尺寸、缩放和设备像素密度绘制文字，缓冲区上限为单边 4096 像素、8 Mi 像素。图片解码与绘图缓冲区复用，过期帧取消；透明区域完整替换。预览缩放不改变文档坐标或导出分辨率。

导出按文档及保存范围计算尺寸，内容区排除隐藏层和编辑批注，并考虑旋转边界。媒体保存的格式和尺寸上限见[使用指南](../01-user-guide/02-workbench.md#保存与导出)，素材及快照必须走[带认证的资源 URL](05-architecture-performance.md#访问与文件完整性)。

## 两种保存目标

| 目标       | 保存契约                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 工作区制作 | 一次编辑会话复用 `createPersistentImageDraftRepository`，初次载入记录观察版本；`EditorSaveQueue` 串行保存，失败保持 dirty，切换前等待 flush |
| 媒体库文件 | `/api/image_edit_history` 返回文档及当前文件摘要，`/api/edit_image` 提交合成图片、文档和 `parent_revision`                                  |

工作区每次写入读取新索引，但不能重建会话仓储或刷新已观察的文档版本。事务拒绝其他窗口修改及已删除制作文件，成功后才更新观察值和缓存。

媒体的 `parent_revision` 是打开时文件的 SHA-256，成功覆盖后更新为返回记录的 `output_hash`；它与稳定的记录 `id` 用途不同。准备快照和发布前检查源版本，过期请求拒绝保存。覆盖更新一个记录，副本另建记录，不切换当前原图编辑目标。`mergeSavedMediaAssets` 仅在覆盖时更新当前文档的快照映射，保存副本只登记输出文件，保留原图快照的归属和修订。

项目目录中的 `omnigallery-edit-history` 保存记录、输出摘要映射和去重素材快照。各次编码加入独立修订标识，BMP 使用私有尾部及更新后的文件长度，避免相同像素串用记录；摘要映射支持文件改名。媒体文档最多 500 图层、JSON 序列化字符数不超过 800 万，超限明确拒绝，保存范围为 `content` 或 `canvas`。

## 回归验证

模型测试覆盖旋转、缩放、裁剪、文字排版、分组排序及完整恢复；会话、仓储和 API 测试覆盖副本快照归属、多窗口修改、删除、同名副本、过期源版本、BMP 隔离与发布失败回滚。

真实画布性能用例见[测试素材](../../test_data/README.md)：4K 画布、五个 4K 图片源和一个文字图层，核对属性同步、单次撤销、取消及重新打开。模型测试不能替代 WebView2／浏览器的视觉和手势验证。
