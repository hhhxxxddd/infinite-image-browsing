# 应用存储实现

## 启动与目录契约

生产入口统一为 `omnigallery.server:create_app`。CLI、开发服务及打包入口先完成 `storage.layout.ApplicationStorage.prepare()`，再导入配置、数据库、日志及工作进程。`omnigallery.app:create_app` 是内部组合工厂，供已准备环境和隔离测试使用，不作为部署入口。

`OMNIGALLERY_DATA_DIR` 指定默认根，`<默认根>/storage.json` 版本 1 保存当前目录、待迁移目录、迁移标识、错误和旧目录记录。设置页修改定位文件，不热切换进程内路径。默认根及当前根持有操作系统文件锁，退出或进程终止后自动释放。

`storage/layout.py` 中 `DIRECTORIES` 是受管子目录的唯一清单。配置从当前根派生 SQLite、项目数据、缓存与模型路径；运行环境从同一根派生自己的子目录。启动工厂还设置 `tempfile`、TEMP／TMP／TMPDIR、pip 和 Hugging Face 缓存位置；独立 AI 进程清理继承变量后重新指定受管 pip 缓存。

桌面宿主只传入默认应用数据根和迁移专用旧缓存位置。桌面日志按定位文件解析当前根，每次追加时打开文件，不持有迁移前目录的日志句柄。三类托管运行环境的 `active.json` 保存相对版本目录；独立 Python 的 `_pth` 同样使用相对路径，根目录迁移无需重新下载。

`project_files` 固定使用 `project-data`，`archive_settings` 固定使用 `exports`；两者不再独立写配置。应用根及旧受管目录排除媒体扫描。原媒体和显式外部模型引用不主动搬迁。开发工具链、前端构建与浏览器偏好不属于受管业务数据。

## 迁移与升级

安排迁移只验证绝对路径、空目录、可写性和目录关系，并原子写入 `pending_directory`／`pending_id`。下一次启动在数据库与工作进程启动前持锁复制：

1. 目标 `.storage-migration.json` 记录来源及本次标识，`.storage-migration` 作为暂存区。
2. 按受管清单复制，文件校验长度和 SHA-256。SQLite 使用 backup API 并执行 `integrity_check`，不直接复制活跃 WAL／SHM。
3. 在副本中改写受管路径前缀：数据库的设置、工作区状态／来源和媒体目录引用，以及项目／模板 JSON 文档。非受管外部引用保持不变。
4. 发布各子目录，最后原子切换启动定位文件；源目录完整保留。切换失败回滚本次发布的子目录，继续使用源目录。
5. 中断后只有来源及标识均匹配的暂存区可清理重做。目标被其他文件占用时拒绝覆盖；使用中的目录、符号链接和 Windows 目录联接拒绝迁移。

首次升级使用 `.storage-upgrade.json` 日志导入旧版 DB／CACHE／PROJECT_DATA／MODEL 路径和数据库中的 project_storage／archive 配置。归档仅导入 `omnigallery_archive_*.zip`，不搬走任意归档父目录中的个人文件。重写数据库前保留 `db/backups/before-unification.db`；日志记录来源及完成状态，避免发布定位文件失败后重复导入产生冲突。升级完成后删除旧分项设置，忽略旧分项环境变量。

迁移是复制校验后切换，空间需容纳完整副本。未知的根级文件不迁移；开发构建和 QA 文件不能通过迁移清理删除。备份恢复的用户操作边界见[存储与备份](../01-user-guide/04-storage.md#备份与恢复)。

## 缓存与持久文件

`maintenance.py` 遍历受管类别统计占用，跳过链接和不可读项目并返回计数。清理使用白名单，不递归清空整个 cache：

- 图片缩略图 `.webp`，以及此前进程遗留的缩略图 `.tmp`。
- `video_cover` 下带 `.generated` 标识的自动封面。
- `tmp` 中修改和创建时间均早于本进程启动的普通文件。

生成和读取缓存用 `use_cache` 租用计数；清理在同一锁内检查活跃租用、目录边界、文件时间与大小，再删除。HTTP 缩略图／自动封面在租用内读成响应字节，避免延迟 FileResponse 读取时文件已被清理。

用户选取的视频封面新写入 `project-data/media-covers`，优先于自动缓存读取。没有生成标识的旧视频封面继续读取且保留。模型、安装环境、模板、归档、编辑历史、下载缓存和日志不进入清理白名单。

## HTTP 接口

| 接口                                                    | 契约                                                                       |
| ------------------------------------------------------- | -------------------------------------------------------------------------- |
| `GET /api/application_storage`                          | 当前／默认／待迁移目录、重启状态、错误、备份和派生子目录                   |
| `PUT /api/application_storage`                          | `{ directory: 绝对路径 }` 安排迁移；提交当前目录取消安排；路径错误返回 400 |
| `GET /api/application_storage/usage`                    | 总字节数、可清理字节数、各类别文件数与跳过数                               |
| `POST /api/application_storage/clear-cache`             | 返回实际释放字节数、删除与跳过文件数                                       |
| `GET /api/project_storage`、`GET /api/archive_settings` | 兼容只读派生路径；旧分项 PUT 已移除                                        |

所有接口经过认证；修改目录、清理缓存必须有写权限。磁盘操作由同步路由在线程池运行，迁移只在启动时执行。设置界面分别呈现当前目录与待迁移状态，不能在请求成功时宣称迁移已完成。

## 后续模板

`templates` 预留给应用级共享资源，不按媒体库或工作区分别配置目录。当前不实现文字模板保存、模板索引或套用；后续可按类型与版本定义文字分组、完整图片文档、布局及音视频模板。模板正文、引用素材和预览需有独立持久化契约，不能存入可清理缓存，也不能仅保存来源工作区的临时地址。

## 回归

单测与集成测试使用临时目录，覆盖全部子目录、数据库和文档引用、真实编辑快照、相对运行环境指针、旧版导入、校验／发布失败、中断重试、目标占用、进程锁、权限及缓存使用中跳过。子进程测试验证生产工厂先迁移后导入配置。还需在目标平台核对真实大模型迁移与桌面安装包启动；字节复制和路径测试不等同于目标设备的推理验证。
