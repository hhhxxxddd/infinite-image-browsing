# 06 · React + Mantine 界面

> React + Mantine 是网页和桌面的唯一界面，唯一入口为 `/`。Vue 页面、运行时和构建依赖已移除；现有媒体、工作区和浏览器旧版记录继续兼容读取。

## 入口与模块边界

- `frontend/index.html` 加载 `frontend/react/main.tsx`，Vite 只构建这个 HTML 入口。后端 `/` 返回 `index.html`，Tauri 默认也从 `index.html` 启动。旧版页面入口已删除。
- `react/main.tsx` 在渲染前调用 `initializeApiClient()`，使 Web 和 Tauri 桌面端使用同一后端地址与鉴权处理。
- `react/App.tsx` 负责外壳、一级导航、主题、路由、鉴权弹窗和页面错误隔离。页面与编辑器按需加载，加载失败时保留导航外壳。
- `react/features/media`、`react/features/workbench`、`react/features/discover`、`react/features/settings` 各自负责页面。编辑器通过 `react/features/editors/EditorHub.tsx` 占据全屏，不叠加主导航外壳。
- `react/design/navigation.tsx` 提供 `useEditorNavigation()`；业务页面调用 `openEditor(kind, draftId?)`，关闭时返回原页面。编辑器种类为 `image`、`video`、`audio`、`ai-image`、`ai-audio`、`ai-video`。

React 路由暂以查询参数表示：`?page=workbench`、`?page=discover`、`?page=settings`、`?section=image`、`?section=folders&path=<目录>` 和 `?editor=audio&draft=<id>`。旧版 `?action=open/view/pane` 链接可映射到 React 媒体、目录、预览、图片对比或相应一级页面；其中 `pane` 支持 local、empty、img-sli、workbench、global-setting、random-image。图片对比支持滑动与并排视图，并列显示两图的生成信息。目录下方恢复旧版 `omnigallery:tab-layout:v1` 中的本地目录和图片对比视图；React 后续打开和关闭的视图分别保存在 `omnigallery:react-open-folders:v1`、`omnigallery:react-open-comparisons:v1`，保留旧版本布局记录以兼容迁移。`pushState` 写入导航，`popstate` 响应浏览器前进／后退。切换一级页面会关闭编辑器；打开编辑器会保留原页面参数，便于返回。后端资源 ID 仍作为 ID 传递，不从展示名称推断。

## 视觉规则

Mantine 负责控件、浮层与主题状态；`react/design/theme.ts` 统一主色、文字、字号、圆角和控件高度。`react/design/global.css` 定义外壳和语义色变量；页面 CSS 应优先使用变量，避免各页面重复设定灰阶和边框。

| 变量                                                               | 用途                     |
| ------------------------------------------------------------------ | ------------------------ |
| `--omni-canvas`                                                    | 工作区域底色             |
| `--omni-surface` / `--omni-surface-soft` / `--omni-surface-raised` | 卡片、次级表面与悬浮表面 |
| `--omni-border`                                                    | 容器边框、分隔线         |
| `--omni-ink` / `--omni-muted`                                      | 主要文字与辅助文字       |
| `--omni-accent-ink` / `--omni-accent-soft`                         | 交互强调文字与背景         |
| `--omni-action-fill` / `--omni-action-hover` / `--omni-action-ink` | 主要按钮、悬停与文字     |
| `--omni-nav-ink` / `--omni-nav-selected`                           | 导航选中文字与背景       |
| `--omni-success-*` / `--omni-warning-*` / `--omni-danger-*`        | 状态文字与对应底色       |
| `--omni-shadow-float`                                              | 浮层阴影                 |

浅色和深色在同一套语义变量下切换。窗口宽度不超过 1000px 时，侧边栏默认收起成图标栏；用户可手动展开或收起，选择保存在 `localStorage` 的 `omnigallery-react-sidebar`。主题由 Mantine color scheme manager 保存。交互反馈应温和、短暂，并遵守 `prefers-reduced-motion`。菜单、弹窗、表单等通用控件用 Mantine 组件，业务页面 CSS 只定义排布及专有视图。

主侧栏、已打开目录标签和设置分类的选中态保持石墨银灰。主要 `filled` 按钮共用蓝色：浅色背景 `#356CB6`、白字，深色背景 `#8CB8ED`、文字 `#15283E`；添加、新建、生成和导出使用此口径。媒体选择、数量徽章和操作焦点共用柔和蓝色：浅色 `#E8F0FB` 底／`#28558A` 字，深色 `#24364D` 底／`#B8D5F8` 字。编辑器始终采用深色变量。普通控件与来源标签用中性灰；成功为绿、警告为琥珀、错误与收藏为红，橙／黄合并为同一琥珀色，青绿成功提示合并为同一绿色。用户自定义标签、画布内容和媒体本身的颜色保留。AI 搜索光晕通过 `AISearchGlow` 绘制在滚动区域外，跟随搜索框位置、尺寸及聚焦状态，允许延伸到侧栏边界；普通搜索不显示光晕。

常规文字及状态徽章的前景／背景对比度至少 4.5:1，必要的选中边界和片段边缘至少 3:1；不可只替换背景而保留原文字颜色。`react/design/colorContrast.test.mjs` 检查浅深主题的主要按钮、数量与状态徽章、导航，以及固定深色编辑器的片段文字和边界。填充控件的前景色按两种主题分别解析，普通未指定颜色的 `light` 按钮和页签使用中性灰。

React 标签配置用 `react/design/tagColors.ts` 的一排六色预设替代自由取色：石墨灰、蓝、青蓝、绿、琥珀、红。预设搭配白色标签文字和选中色勾选，对比度均不低于 4.5:1；内置 `like` 默认红色 `#B8474E`，历史空颜色同样按此展示。已保存的其他自定义颜色保持到用户重新选择；标签行的小色点显示当前颜色，既有改名、分组拖放和自动规则继续保留。

设置、工作台和挑一挑共用 `react/shared/PageFrame.tsx`：标题在顶部连续区域，正文在下方圆角容器内独立滚动。标题不参与正文滚动，设置分类吸附在正文内并在低窗口高度下独立滚动；切换设置分类或工作台页面时回到正文顶部。外层 `.omni-content` 不再和这些正文同时滚动，避免内容进入顶部区域。媒体库保留自身的搜索和筛选吸附布局以及独立 AI 光晕层。

挑一挑与媒体库共用 `MediaArtwork`、`MasonryGallery`、图库卡片样式和 `MediaGalleryViewOptions`，缩略图大小及“显示信息”沿用相同本机偏好。卡片使用相同混排、7px 圆角、悬停放大、收藏位置、音视频播放标识和底部文件名／标签遮罩，不另设卡片信息底栏。挑一挑仍点击预览，保留类型切换、随机换批、最近 20 批历史、收藏和标签操作；切换类型或批次回到正文顶部。挑一挑和工作台取消固定最大宽度后的居中布局，正文随窗口铺开，标题与正文共用横向留白；工作台作品和制作文件网格按可用宽度增减列数。

挑一挑顶栏左侧放媒体类型切换，右侧放上一批／换一批；下排左侧放批次数量，右侧放卡片大小与“显示信息”。不再重复页面图标、标题、说明或逐项查看按钮，点击卡片进入可切换的预览。图库、挑一挑和媒体预览的标签编辑共用 `MediaTagPicker`：分组标题与可多选标签直接展示，保留未分组，支持按显示名称、原始名称及分组名称搜索，搜索不修改选择；选择先保存在草稿中，保存时一次提交目标标签集合；后端事务写入，失败保留草稿并可幂等重试。批量标签选择也按分组排列，快捷打标统一复用 `MediaTagMenu`，带搜索、分组和已选勾选。

设置页随主内容区铺开，顶部与正文共用留白，宽屏下表单控件宽度最多 440px；按正文和卡片实际宽度切换导航及表单布局，避免侧栏展开后控件拥挤。分段切换控件共用固定分隔线，切换选项不隐藏相邻分隔线。

媒体库筛选使用 `MediaFilterPanel`，在主内容区右侧浮动，没有整页遮罩或焦点锁定，背景媒体仍可浏览和选择。标题与重置／应用／清空按钮固定，筛选内容独立滚动；宽高及比例字段在面板内使用两列，每个输入框占满所在列。标签默认按组收起，搜索时展开匹配组；标签、尺寸和包含子文件夹先修改草稿，应用后统一生效，重置恢复已应用条件。关闭按钮或 Escape 收起面板并在合适时恢复筛选按钮焦点，原查询接口及组内任选、组间同时满足规则保持一致。

`MediaFilterForm` 在每次打开时从已应用条件创建本地草稿，输入、选择标签、排除标签及开关不再更新媒体库或工作台素材选择器的状态；仅应用时向调用方提交条件。`MediaFilterTags` 将标签区与尺寸输入隔离，缓存分组及排除选项，搜索输入立即回显，结果使用 `useDeferredValue` 更新并保留分组实例及手动展开状态。避免将草稿重新提升到列表页面，或通过变化的搜索 key 重建全部分组。共用标签编辑器同样将输入回显与结果更新分离；性能验收应同时观察输入响应和媒体卡片是否产生无关重绘。

媒体选择使用浅比较缓存的 `MediaCard`，标签列表、选择回调及操作对象保持稳定；勾选仅更新状态变化的卡片，单选／多选切换时同步更新所选卡片的菜单模式。`useCallbackRef` 使批量菜单及拖动操作读取当前选择，拖动路径在拖动开始时生成，避免把每次变化的选择数组传入全部卡片。不要通过忽略回调的自定义比较函数掩盖更新，否则批量操作会引用旧选择。`LazyModal` 只在打开和关闭过渡期间构建弹窗内容，结束关闭动画后释放内容；工作台素材选择器同样缓存单张卡片与稳定的选择回调。本机开发模式的同一媒体库 100 张卡片序列，脚本耗时为单选 368→51ms、追加四张 1170→190ms、取消一张 467→83ms、清除选择 141→31ms；素材选择器 60 张卡片下四次切换 179→51ms。已验收 Shift 范围选择、反选、快捷键全选、预览分页、标签分组及增减选择后的批量目标数量；测量值用于本机前后对比，不等同于所有设备的交互延迟。

全局操作提示位于当前工作区域底部居中，自动避开媒体库多选操作条及编辑器素材条、播放控制。成功提示显示 2.5 秒，普通信息 4 秒、警告 6 秒、错误 8 秒；悬停或聚焦时暂停关闭，重复操作替换同一调用方的提示，最多显示三条。失败消息应明确使用 `useNotice` 的 `{ kind: 'error' }`，避免沿用成功颜色与时长。

React 品牌为“星空馆”，图标采用“星轨＋石墨”，字标使用字重 500、字距 1px 的现代黑体。外观采用石墨灰基础表面：浅色底色 `#f7f7f7`、侧栏与顶部 `#eeeeee`、白色面板；深色底色 `#171819`、侧栏 `#202123`、面板 `#252628`。导航浅色使用 `#454852` 字／`#e3e4e7` 底，深色使用 `#c6c8cf` 字／`#393b42` 底，与蓝色业务操作区分。Mantine 主色为 `blue`，浅／深主题分别使用第 6／3 档，填充控件分别解析两种主题的前景色，避免浅底白字。普通控件与图库卡片圆角统一为 7px，一般容器 10px、弹层与编辑器属性面板 14px。顶部与侧栏为连续表面，内容区从顶部下方以 18px 左上圆角衔接，不设置贯穿顶部的竖直分隔线。侧栏宽度切换使用 240ms 过渡，文字同步淡出；系统减少动态效果时禁用过渡。图库保持混排、选择与排序行为，悬停只放大图片至 1.08、过渡 500ms，卡片和操作按钮保持原尺寸。

界面工具图标继续统一使用 Tabler，导航图标为 19px、线宽 1.8；填充图标用于收藏等明确状态，项目品牌图标使用共用 SVG。AI 搜索开启后显示银白至浅蓝流光边缘与短距离光晕，输入区域保持清晰；关闭后恢复普通搜索框，系统减少动态效果时使用静态亮边。全屏编辑器共用 `--omni-editor-*` 的不透明中性灰表面、蓝色强调、文字和边界；音频／图片／视频片段统一蓝灰色，以名称和图标区分，字幕与标记统一琥珀色，峰值音量表保留绿／琥珀／红阈值，画布输出和棋盘格不随界面配色改变。

图库搜索框左缘对齐下方内容面板的外边缘，结果工具栏与图片墙共用 12–16px 横向留白。结果工具栏在搜索区下方留出 8px 间距，使用实色表面与细底边。页面顶部保持清晰；滚动超过 12px 后，一层独立的 24px 淡投影与 3px 模糊层从底边向下延伸，通过透明遮罩逐渐减弱，回到顶部时隐藏，浅色模式进一步降低投影强度。延伸层不拦截指针，不将筛选条本身变透明，不使用白色渐隐。

目录根视图复用图库的顶部搜索、添加文件夹按钮和结果工具栏，数量与刷新位于第二行；节点图使用相同工作区域底色与低对比点阵，节点图标在浅深色下均使用强调色文字。保留图标编辑、拖放和上下文菜单。目录展开／折叠选择及总览纵向、节点图横向位置保存到本机；返回、刷新和重新打开后恢复，改名／移动沿用下级展开记录。图库更多菜单不再提供重复的“逐张查看”入口，逐项切换由媒体预览承担。

常规界面使用 12/13/14/16/20 px 的 Mantine 字级；全屏编辑器在 `.react-editor-shell` 中覆盖回紧凑字级，避免时间线操作区被放大。`react/design/i18n.tsx` 复用旧版四份语言资源，额外补齐 React 外壳和设置的文案。语言首次打开优先读取后端 `app_fe_setting.global.lang`，缺失时回退到 React 本机副本、旧版本保存的设置或系统语言；用户切换语言会写回后端并保留本机副本。导航、设置分类、外观、通用和浏览设置，以及媒体浏览／筛选／详情／常用操作会即时切换；用户文件名、标签、元数据、动态错误及工作台、编辑器与 AI 高级表单尚未全量翻译，四语言不能视为全站验收完成。

媒体预览参考桌面图片查看器，顶部左侧提供带图标的“编辑”和“制作”按钮，悬停说明编辑当前图片（保存副本或覆盖原图）与在工作台建立独立制作文件的区别，组后以细线分隔旋转、收藏、下载及删除操作，文件名居中；底部保留文件规格、列表位置、缩放滑块，媒体描述开关位于信息栏开关左侧，最右侧为全屏开关。图标统一使用 20px 细线条与 34px 点击区域，常态透明，悬停和选中时才显示中性反馈，收藏保持红色。详情侧栏使用文字页签，标签与 AI 标签建议只在“描述”显示。宽度不足 700px 时详情移到画布下方独立滚动，“编辑”和“制作”仍以图标加文字留在顶部；制作场景提供的额外操作继续保留。更多菜单仅在桌面版支持“用其他应用打开”的媒体上显示。预览画布实际挂载后绑定尺寸观察与滚轮，信息栏展开收起采用 220ms 布局过渡与轻微位移、淡入淡出，窄窗口使用纵向过渡；收起后保留当前媒体的页签和已加载信息，切换媒体时不预加载隐藏的信息栏，隐藏内容不参与键盘焦点或无障碍读取。系统启用“减少动态效果”时关闭这些过渡。开关侧栏、重新打开、改变窗口和全屏时都按当前可用空间适配图片；全屏保留完整工具栏，标签、描述、参数和歌曲编辑弹窗挂到全屏容器内。

## 后端契约与设置

`react/shared/apiClient.ts` 是唯一的 React HTTP 入口，提供 `apiFetch`、`apiRequest`、`apiUrl`；业务模块不要再各自实现鉴权、后端端口或 fetch 包装。后端返回 `secret_verification_failed` 时，由 App 中的 Mantine 弹窗请求访问密钥后重试。`mediaApi` 合并同时进行的相同元数据读取，完成或失败后移除，写入前后失效；它不缓存已完成结果，避免重新打开时读到旧数据。

预览音频只请求一次歌曲元数据供封面、歌词和信息栏复用，时间更新仅在当前歌词行改变时发布状态；图片 EXIF 按元信息页签加载，并按路径／版本复用。全屏中的编辑弹窗保留自身快捷键范围。标签编辑通过 `PUT /api/media_custom_tags` 或工作区产物 metadata 的 `tag_ids` 提交完整自定义选择，空数组表示清空；旧读取结果不能覆盖新编辑会话。挑一挑最近 20 批历史与标签缓存对应，排除路径最多保留最近 256 个；切换语言不重新选批次或改变媒体类型。后端同步元数据与标签操作在工作线程执行，图片元数据读取及保存沿用路径权限检查；批量生成信息分块查询，避免逐项 SQL。

设置页接入项目数据目录、归档目录、网络代理、FFmpeg／PyTorch 运行环境、标签分组与自动打标规则、浏览偏好、Qwen 本地模型、Comfy 连接与模型目录、图片 AI 接入和 OneDrive 同步。浏览与通用偏好启动时优先读取后端 `app_fe_setting.global`，缺失时沿用 React 本机副本或旧版本保存的设置；修改时先更新当前页面和本机副本，再串行读取并合并写回后端，保留旧版管理的其他字段及 `ignoredConfirmActions` 子项。媒体页监听 `iib-react-browse-preferences-changed`，实时应用缩略图开关、最大短边、卡片基准宽度和自动索引检查。后端只读或保存失败时页面显示错误。重建媒体索引与 Qwen 向量索引都需要用户在设置中确认后才发起。

运行环境页支持 Windows x64 源码版与桌面版安装、更新和检查独立 PyTorch 环境。源码版未安装时显示“当前 Python”，沿用启动后端的环境；安装成功后自动改走独立 worker。环境详情使用信息图标与加减展开按钮。FFmpeg 自动安装仍仅支持桌面版，已用于音频制作和视频 MP4 导出。Qwen 标题旁的问号以表格说明支持系列及量化；Embedding、Reranker 与 Instruct 均可选择 GGUF，下载与已有模型共用一个路径字段。Instruct 选择 GGUF 后隐藏 PyTorch 量化选项，通过应用托管引擎生成描述、提示词与标签建议。安装、云端调用及完整模型推理需要目标环境验收；界面状态不能替代服务可用性验证。

AI 接入使用“本地模型／服务连接／使用设置”三个页签，切换时保留各页签的输入草稿。顶部摘要读取已保存的图片理解服务；模型“已选中”与服务“使用中”分别显示。在线服务下拉只列 Comfy Cloud 和 OpenRouter；本地 GGUF 统一由应用托管，不提供外部服务连接。服务配置保存、启用和通用模板保存都通过 `PATCH /api/image-ai/config` 提交对应字段；后端在配置锁内合并已保存值，保留其他模型、工作流映射、模板和密钥。启用本地模型只修改 provider，不受未启用的 Comfy 工作流映射是否完整影响；旧版完整 PUT 接口保留。工作台的工作流预设入口保持原位置。

媒体目录可直接浏览后端 `/files` 列表，包括尚未入索引的文件；常规媒体库仍使用索引查询。旧版 `?action=open/view` 可直达目录或单文件预览。目录中的“查看全部内容”已接入 `directoryWalk.ts`，逐目录读取真实磁盘并分批显示，支持排序、路径边界校验和失败重试；它与“包含子文件夹”的索引搜索是不同入口。目录查看选项还提供 1–600 秒轮询刷新，以及带当前浏览模式的 Web 分享链接。媒体预览在已加载列表末尾继续取下一页，方向键、滚轮和按钮共用续页逻辑；触屏上下滑动也可切换项目。预览中的“新建制作”选择作品后会在同一次工作区写入中创建制作文件、纳入源素材，并打开编辑器；图片制作会读取源尺寸，以完整显示的方式铺入首个图层，音视频制作先将源加入素材池。返回和切换编辑器前等待当前修改保存；保存失败时留在原编辑器并提示错误。

图片理解的 Comfy 工作流可导入 API 格式 JSON，并设置图片输入、提示词和输出节点；全局图片创作的模式、Router 模型与并行数也可设置。Comfy 的连接与密钥配置读取完成前显示检查中，失败时显示状态未知及错误，不将未读取状态误报为“未配置”；服务端只返回密钥配置标志与来源，前端不回显已保存密钥。Studio 工作流预设统一在工作台入口列出、导入、保存和删除，设置页不再重复放置这套配置；图片节点可指定主图、参考图或内部角色，参考图可排序（最多 13 张），遮罩可选主图 Alpha 输出或独立 `LoadImageMask` 节点并开关，正向／负向提示词和多个结果节点可映射。可调参数支持数值、文本、开关、选项四类；数值范围与滑块、多个字段和选项值可配置，前端按后端约束预检重复或保留字段、类型与容量，后端仍做最终校验。音频与视频工作流预设也可在工作台配置入口修改名称、用途及可调参数，但尚不能作为已经接入的音视频 AI 服务使用。迁移期间不能因为界面出现服务名称就将其标为就绪。

“挑一挑”调用现有 `/pick_media`，按全部／图片／视频／音频分批随机挑选；最近 20 批可返回浏览，已展示路径用于避免短期重复。卡片可进入原图／视频／音频预览，右侧复用媒体库详情面板，可查看和编辑描述、生成信息、音频歌曲信息及自定义标签；卡片可直接收藏或打开标签菜单。无媒体、只读或服务失败时给出对应状态。

React 音频编辑读取后端 `X-Audio-Level-Peaks`，显示实时左右混音电平、峰值和过载状态；试听按后端 12 秒片段上限连续请求与衔接。跨片段播放及非静音电平变化需在真实音频样本中验证。

React 视频编辑通过 FFmpeg 导出 MP4，结果保存为工作台产物。全屏编辑器沿用专业布局：顶部保存与导航、左侧工具、中央画布或时间线、右侧属性、底部横向素材条。图片画布与 AI 图片编辑支持保存后继续编辑；AI 图片、音频、视频入口可在同一制作文件内切换，音频和视频仍是不可提交任务的占位页，切回图片时重新读取已保存的主图、参考图和配置。Studio 工作流已有可视节点图及节点映射面板。当前能力仍有边界：四语言尚未覆盖工作台、编辑器和设置高级表单的全部文案，媒体动态内容仍按原文显示；运行时参数预览及图片工作流的真实 ComfyUI 端到端提交仍待验收。

## 开发与验收

在 `frontend/` 运行 `npm run dev` 后访问 `/` 验收当前应用。`npm run check` 依次运行格式、ESLint、统一 TypeScript 检查、React／领域模型测试和构建；产物只包含 `dist/index.html` 一个入口。每个页面应使用真实后端数据核对浅／深色、窗口宽度、滚动、关键操作及数据写入路径。
