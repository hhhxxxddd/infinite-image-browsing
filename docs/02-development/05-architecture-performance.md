## 1. 模块与边界

前端依赖方向是 `app → features → shared`。`features/application` 提供跨模块导航、偏好和事件契约；业务模块通过显式 public 入口组合，组件保持独立懒加载，纯模型入口不加载浏览器或服务依赖。ESLint 检查反向导入、循环、any 和非空断言，包含 Vue 模板。

| 前端领域 | 主要职责 |
| --- | --- |
| media-library／media-preview／media-comparison | 收录浏览、选择筛选、预览会话、比较 |
| generation-metadata | 参数解析与读写、资源、工作流识别、共用输入 |
| image-editor | 图层模型、渲染、画布交互、工具、撤销；通过宿主接口保存 |
| media-editor | 声音时间线、可见波形、片段操作及分段试听；后端 FFmpeg 混音与导出 |
| workspaces／ai-workflows | 制作文件仓储、工作区产物、成果关联、任务、工作流配置和加工 |
| settings／organize／discovery／exports | 设置、整理、发现、导出 |

预览由 `usePreviewMetadata` 管当前媒体元信息与请求失效，`MediaDetailsPanel` 展示。编辑器输出和图层拖拽分别封装；工作区宿主注入绑定工作区的 `StudioDraftRepository`，切换前等待旧会话保存成功。媒体库保存持久编辑记录；工作区产物保存为文件，作品、制作文件及编辑文档保存在 SQLite。

工作区状态通过 `/api/workspace_state/{workspace_id}` 读取与批量更新，`workspace_state` 保存按工作区隔离的作品／图层／AI 状态，`workspace_state_revision` 保存事务版本、迁移状态和删除标记。前端只读内存缓存供纯仓储同步读取，修改在暂存副本中完成，服务器使用同一 SQLite 事务提交文档、索引与关联，成功后才发布缓存及保存状态。版本冲突拒绝覆盖；删除标记阻止旧窗口自动保存或浏览器备份重新创建工作区。首次读取会幂等迁入已有 localStorage 状态；没有旧数据的浏览器不会占用迁移机会。媒体改名在同一数据库事务中更新图层路径和 AI 路径键，提示词及文字内容不变。数据库备份包括作品及制作文件，项目文件目录仍须单独备份。

AI 制作文件不固定任务用途。`ProductionDraft.aiPurpose` 只作为初始任务的兼容默认值，旧文件默认编辑。`AICreationPage` 管顶部媒体导航（图片／音频／视频），AI 图片面板内部选择生成／编辑；`ai-production-session-v1:{workspaceId}:{workId}:{productionId}` 保存当前媒体入口和最后图片任务，纳入状态迁移、事务和文件删除清理。切换前保存当前任务及配置，失败或未确认裁剪时不切换；图片子组件按首次访问挂载，切走后保留会话，隐藏编辑画布停止渲染，素材条只在可见子页挂载。卡片统一为“AI 生成”，次级标签、预览及来源对应最后图片任务。

生成和编辑共用制作文件 ID，但配置使用不同命名空间：生成配置使用独立的 `ai-production-generation-*` 状态键，无须伪造画布文档；提交版本为用途、方式和参数的内容哈希。`TaskRequest.purpose` 默认编辑，生图请求使用禁止额外字段的纯文字 schema，Router 不发送图片，Cloud 工作流不上传图片；任务固定用途和文件归属，产物来源为 `ai_image_generation`。素材预览借用已解析的提示词，不建立图片输入关联；生成预览只筛选该文件的 `ai_image_generation` 产物。

图片结果映射为有序 `output_mappings: [{node_id, label}]`，旧 `output_node_id` 按一个映射读取；显式空列表表示取消映射。Cloud 收集各映射节点的全部图片，Router 收集所有候选中的图片。任务新增有序 `results`、`document_id`、`purpose`，保留 `artifact_id` 指向首张，旧任务从产物关联恢复文件及用途。每保存一张立即写任务记录，后续失败保留部分结果；来源、源图和元信息按图片保存。

声音时间线键为 `omnigallery:audio-timeline-v1:<workspaceId>:<draftId>`，纳入状态事务、路径改名及制作文件／作品／工作区删除。片段保留源路径、源起点和包络坐标，按 48 kHz 样本取整；试听逐次渲染最多 12 秒，导出使用相同流程。波形流式解码为 4096 个峰值，仅绘制可见窗口，缓存存放于项目目录的 `audio-waveforms`，可重建；时间线、产物和输入快照属于持久数据。

`AIMediaPlaceholder` 的音频／视频入口仅提供未接入说明、规划任务、笔记及素材条，没有对应提交 API、服务配置、播放器工作区或输出管线。未来接入需按任务定义 schema、输入角色与快照、请求适配、后台执行、媒体预览及产物保存；编辑任务保留实际输入来源，纯生成任务不伪造来源。能力清单见 [工作台](../01-user-guide/02-workbench.md#当前能力与后续规划)，不得把占位入口视为已实现能力。

产物的 `document_id`／`document_revision` 标识直接所属制作文件和内容版本。图片制作通过输入交接建立同一作品中的 AI 分支，`ProductionDraft.source` 保存上游文件 ID、版本、范围、图层和快照引用；按来源 ID 与范围匹配续编，名称不参与关联。`workspace_artifact_lineage` 仅在编辑任务提交时固定上游来源；同一文件切到纯文字生成时不继承编辑来源，后台结果不依赖当前页面或随后修改的状态。图片卡片查询自身和派生分支的产物，AI 卡片只查询直接所属产物。

`/api/workspace_inputs` 保存独立输入快照，使用已有图片文件与缩略图通道，`workspace_artifact_input` 标记所属分支并从产物列表排除；输入不能同步媒体库。创建分支先保存快照，再通过状态事务写制作文件与 AI 文档，事务失败需确认是否已提交后再清理快照。删除 AI 制作文件或作品后清理其输入，来源画布删除不删除派生分支。任务名称由服务端按 `studio_task_sequence` 分配制作文件内连续编号，删除历史不复用编号。

图片导出按实际保存范围计算版本，卡片只复用相同版本的 PNG 图片制作产物，避免误用 AI 结果、JPG 或完整画布导出。产物重命名、删除在服务端事务中维护作品的素材／成果关联，删除还清理对应 AI 输入，保留画布图层以显示缺失素材。同步接口必须携带 `work_id`，服务端核对该产物仍在作品成果中，再复制并建立媒体索引。

后端 `omnigallery/app.py` 装配各领域：library 管索引与文件，metadata 管解析，image_editing 管保存与快照，workspaces 管作品／制作状态、产物与任务，ai／search 管模型和检索，storage／settings 管持久配置，infrastructure 管数据库、认证、路径、网络和平台。routes/service/repository 按需要分工，通用媒体实体使用 `media`。

数据库只存索引和应用数据，原媒体留原处；项目数据目录保存工作区文件及编辑快照，扫描主动排除当前和历史托管区。目录权限区分“可导航父级”和“可递归处理授权根”，修改前校验完整源／目标集合。

## 2. 已有性能措施

| 环节 | 当前处理 |
| --- | --- |
| 目录与索引 | 初次只取直接子目录，深层按需展开；纳秒目录时间增量检测；扫描／重建串行 |
| 媒体列表 | 虚拟滚动；选择集合避免每张卡片反复线性查找；默认日期＋ID 范围游标，自定义位置索引游标；瀑布流追加复用位置，图片尺寸每帧合并 |
| 文件夹查询 | 字面路径范围利用索引，Windows 忽略大小写并保留目录边界 |
| 图片与音视频 | 视口附近缩略图加载、磁盘缓存、受限并发；视频 Range 分块，相邻媒体不加载原文件 |
| 编辑器图片 | 每份文档保留当前渲染所需图片，按 32 Mi 像素预算缓存，超预算仍保留稳定子集；文档释放后可回收，原图导出不进入预览缓存 |
| 本地文字搜索 | FTS5 trigram 索引筛选名称／描述候选，原 LIKE 条件核对；不足三个字符或没有扩展时回退；触发器同步新增、替换、改名、描述和删除 |
| 目录封面与文件操作 | 封面流式保留最新四项，不排序全部目录项；同步文件路由在工作线程执行，连接也在该线程取得 |
| 图片向量检索 | 游标分批读取，批量点积，仅保留最佳候选的卡片字段；每批读取结束后再检查文件，避免持有读锁等待慢磁盘 |
| 生成信息 | 紧凑展示不序列化隐藏字段；工作流只在复制时生成完整 JSON；原文映射防抖 180ms |
| 预览会话 | 当前项请求缓存与去重，切换／关闭使旧响应失效；保存捕获原始媒体身份 |
| 工作区 | 素材条初始 16 项渐增；“全部”按实际方形卡片尺寸虚拟化并限制可用视口高度；素材条悬浮图约 200ms 延迟 |
| 后台任务 | 有任务 2 秒、空闲 15 秒轮询，请求完成后才排下一次；最近 100 项优先保留未完成任务 |
| AI 搜索状态 | 10 秒轮询且避免重叠，防止重复索引统计 |

主题聚类可安装 `backend/requirements/search-index.txt` 的 HNSW 扩展来加速大集合候选质心查询；未安装时使用精确余弦比较，保留完整功能。它不是 Qwen 图片向量查询的通用加速器。

后台并发 1–15，未完成队列最多并发两倍且至少 4 个，输入在内存等待执行。限制属于单进程，不能通过多个 worker 共享同一数据库扩容任务队列。重启不重放付费请求。

## 3. 可复现基准

运行 `node frontend/scripts/benchmark-generation-metadata.mjs`。2026-09-27 本机 Node v24.20.0，合成 10,000 节点／2,346,706 字节工作流，5 轮、每轮 20 次的单次中位数：

| 操作 | ms／次 |
| --- | ---: |
| 完整详情，包含补充信息序列化 | 5.728 |
| 紧凑详情，只读展示字段 | 0.001 |
| 检测工作流并生成复制 JSON | 5.316 |
| 仅检测工作流与节点数 | 0.057 |

这是同一实现的不同执行路径比较，不含网络、首次 JSON 解码、Vue 和 DOM 开销；复制时仍承担完整序列化成本，不能据此宣称整站加速比例。

### 媒体查询与布局

运行 `python tools/benchmark_library.py` 和 `node frontend/scripts/benchmark-media-library.mjs`。两者使用合成数据，不修改开发数据库或原媒体。2026-09-28，本机 Python 3.13.15／SQLite 3.53.1／Node 24.11.0：

| 10 万项媒体，每页 100 项 | 优化前 ms | 优化后 ms |
| --- | ---: | ---: |
| 日期排序首屏 | 0.55 | 0.55 |
| 日期排序，约 90% 深度 | 4.46 | 0.56 |
| 自定义排序首屏 | 82.13 | 0.62 |
| 自定义排序，约 90% 深度 | 208.70 | 0.59 |
| 普通文字搜索，无匹配 | 50.84 | 0.11 |

查询数据为内存 SQLite、256 字节生成信息、已知尺寸；文件存在检查被替换，未计文件系统和 HTTP 耗时。优化前五轮、优化后七轮中位数；索引建立不计入查询耗时。首次升级会为已有媒体建立文字索引，需要额外启动时间和磁盘空间。旧 `manual:offset` 游标兼容一次 OFFSET 读取，后续返回位置游标。

布局脚本分别测响应式全量路径和当前原始对象／缓存路径，九轮中位数。五万项尺寸修正约 91.8ms 与 4.0ms；它不包含 Vue 组件更新、DOM 或 GPU 绘制，不能据此推断整个页面帧率。回归测试确认追加复用原位置、尺寸修正／改序／删除／缩放结果与完整布局一致，以及二十个不同图片图层跨帧不再全部缓存失效。

## 4. 容量限制与验证范围

功能样本约 500 项媒体、少量目录，未证明十万图库／网络盘容量。继续优化前先测真实数据：

- **语义搜索：** 已限制批次内存并批量计算，但仍精确扫描候选向量、逐项检查文件新鲜度；极大集合和网络盘仍需评估向量索引与文件监听。
- **目录检测：** 大量目录／网络盘的状态检查有成本；只改文件内容可能不变目录时间，需要文件监听或低频文件级核对。
- **文字搜索与排序：** 短词、正则、纯排除、宽泛匹配仍可能扫描大量记录；首次自定义排序需要初始化位置，移动一组媒体仍需更新受影响顺序。常规两项交换不再遍历已有位置。
- **大工作区／宽目录：** 元数据一次读取；逐步展开的素材仍累计节点，同级子目录也无完整分页，需要容量测试。
- **大图与高并发：** 云端输入排队占内存，推理峰值取决于图片、模型和配置，现有上限不等于资源保证。

回归测试覆盖媒体描述、LoRA 映射、工作流标签、副本与覆盖保存、编辑文档恢复、工作区迁移、事务失败、版本冲突、删除防复活、产物来源及成果同步权限。SQLite 测试连接隔离并显式关闭。格式、lint、类型、测试和构建以统一检查命令及当前 CI 结果为准；界面布局与复杂手势仍需视觉／手工验证。

Tauri Windows 安装包和 Nuitka 仍需目标环境实际构建；真实付费任务、完整大模型推理及复杂拖放手势不属于上述自动检查覆盖范围。
