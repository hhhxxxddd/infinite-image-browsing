# 存储与备份

[文档导航](../README.md) · [工作台](02-workbench.md) · [AI 设置](03-ai-services.md)

## 一个应用数据目录

设置只提供“应用数据目录”。数据库、作品、编辑记录、归档、缓存、模型和应用安装的运行环境都使用固定子目录，不再单独设置项目目录或归档目录。

源码默认位于仓库 `.local`，桌面默认位于系统的用户应用数据位置。设置页“当前使用”显示实际路径；远程网页填写的是**文件服务所在电脑**的路径。

| 子目录          | 内容                                                                 |
| --------------- | -------------------------------------------------------------------- |
| `db`            | 媒体索引、标签、设置、工作区状态与制作文档                           |
| `project-data`  | 工作区产物、输入快照、可编辑历史、合成图片、内置 AI 输入／结果与任务、手动视频封面 |
| `templates`     | 系统共享模板库，包含文字、版式、整页模板文档、预览、配图及可重建索引 |
| `exports`       | 保存到本机的 ZIP 归档                                                |
| `models`        | 在应用内下载的本地模型                                               |
| `ai-runtime`    | 应用安装的独立 Python AI 环境                                        |
| `gguf-runtime`  | 应用安装的 GGUF 推理引擎                                             |
| `media-runtime` | 应用安装的 FFmpeg／ffprobe                                           |
| `cache`         | 自动生成的预览、缩略图和依赖下载缓存                                 |
| `tmp`           | 应用运行时临时文件                                                   |
| `logs`          | 后端与桌面运行日志                                                   |

原媒体、保存到原媒体旁的图片副本、用户主动选择的外部模型保持原位置。系统已有的 Python、FFmpeg 和源码开发工具链也保持原位置；它们不由应用安装管理。浏览器的主题、布局等界面偏好仍由浏览器保存。

## 更换目录

1. 在设置中填写或选择一个空目录，点击“重启后迁移”并确认。当前会话继续使用原目录，也可以取消待迁移安排。
2. 正常关闭并重新启动应用；独立服务需要重启后端，仅刷新网页不会迁移。大模型和运行环境会增加复制时间与所需空间。
3. 启动时复制全部受管子目录，逐文件校验、检查数据库并调整内部引用，成功后才切换。失败时继续使用原目录，在设置中显示原因；可修复问题后重启重试，或取消／换一个目标。
4. 重新打开设置，核对“当前使用”，再检查作品、编辑历史和本地模型。原目录会作为备份保留，不自动删除。

目标不能是当前目录的父／子目录，不能覆盖已有备份或非空目录，也不接受符号链接／目录联接。同一个数据目录只允许一个后端进程使用；需要多个窗口时，连接同一服务。

首次升级会导入旧版独立配置的数据库、项目数据、缓存、模型和应用 ZIP 归档；旧文件保留。不同内容的同名文件会阻止升级，不自动覆盖。旧版分项环境变量完成导入后不再生效。

默认位置保留一个很小的 `storage.json` 启动定位文件，用来找到当前目录；它不是第二个可配置数据目录。迁移后不要删除这个文件。原目录其余备份可在核实新目录正常后自行归档。

## 占用与缓存清理

设置页按上述类别统计占用，并单独显示“可清理”大小；原媒体、外部模型和旧目录备份不计入当前占用。无法读取的项目会提示统计不完整。

“清理缓存”经确认后删除可重新生成的图片缩略图、带自动生成标识的视频封面，以及此前运行留下的临时文件。正在生成／读取的缓存和本次运行创建的临时文件会跳过；结果显示实际释放大小。

清理保留作品、模板、编辑历史、手动封面、归档、模型和运行环境。旧视频封面无法区分是否由用户选择，保守保留；模型下载缓存等尚未列为可清理项，所以“缓存占用”可以大于“可清理”。日志和旧目录备份也不在缓存清理范围内。

## 备份与恢复

关闭应用和后端后，复制整个当前应用数据目录，并保存默认位置的 `storage.json`。原媒体和外部模型需要另行备份。单独保存导出图片无法恢复图层；`db` 与 `project-data` 应作为同一次备份保存。数据库可能包含服务凭据，请按私有数据保管。

恢复时保持备份记录的绝对路径：先停服务并另存现有数据，再恢复当前目录和定位文件，随后启动核对。需要换盘时，先按原路径恢复，再通过设置执行迁移，避免直接移动文件夹导致内部引用失效。应用目前没有一键恢复或跨机器路径重绑定入口。

部署者可在首次启动前用 `OMNIGALLERY_DATA_DIR` 指定默认位置。它决定启动定位文件的位置；更换已有实例的数据位置请使用设置页，不能靠修改环境变量代替迁移。实现契约见[应用存储实现](../02-development/09-storage.md)。
